## Bench Overview

This is a Frappe v16 custom app (`luxury_report`) at `/home/trojan-technologies/frappe-bench/apps/luxury_report`, running on site `local.com`. All `bench` commands must be run from `/home/trojan-technologies/frappe-bench`.

## Common Commands

```bash
# Start all services (web, worker, scheduler, redis, socketio, watch)
bench start

# Run database migrations (after DocType JSON changes or patches)
bench --site local.com migrate

# Build JS/CSS assets for the app
bench build --app luxury_report

# Clear server-side cache (required after hooks.py or DocType changes)
bench --site local.com clear-cache

# Run all tests for the app
bench --site local.com run-tests --app luxury_report

# Run a single test module
bench --site local.com run-tests --module luxury_report.luxury_report.doctype.doctype_name.test_doctype_name

# Execute a Python script or function (e.g., for debugging)
bench --site local.com execute luxury_report.path.to.function

# Install/uninstall the app on the site
bench --site local.com install-app luxury_report
bench --site local.com uninstall-app luxury_report
```

- Pre-commit hooks enforce formatting on staged files

## Adding New Features

### Creating a DocType

1. Run `bench --site local.com new-doctype [DocType Name]`
2. Edit `luxury_report/[doctype_name]/[doctype_name].json` (field definitions, permissions)
3. Create `luxury_report/[doctype_name]/[doctype_name].py` for business logic (lifecycle hooks: `validate()`, `on_submit()`, `on_cancel()`, `before_save()`, etc.)
4. Create `luxury_report/[doctype_name]/test_[doctype_name].py` for tests
5. Run `bench --site local.com migrate` to sync schema
6. Update `modules.txt` if the DocType should appear in the desk sidebar

### Whitelisted APIs

Define functions in the app modules and decorate with `@frappe.whitelist()`:

```python
# In luxury_report/api/your_module.py
import frappe

@frappe.whitelist()
def my_api_endpoint(param1, param2):
    return {"result": "data"}
```

Call from frontend via `frappe.call()`:

```javascript
frappe.call({
    method: "luxury_report.api.your_module.my_api_endpoint",
    args: { param1: "value1", param2: "value2" },
    callback: function(r) { console.log(r.message); }
});
```

### Frontend Hooks (JavaScript)

Add per-DocType client-side logic in `public/js/[doctype_name].js`:

```javascript
frappe.ui.form.on("DocType Name", {
    refresh(frm) {
        // Runs when form is loaded/refreshed
    },
    validate(frm) {
        // Runs before save
    },
    after_save(frm) {
        // Runs after successful save
    }
});
```

For list views: `frappe.listview_settings["DocType Name"] = { ... }`

### Database Migrations (Patches)

1. Create `luxury_report/patches/[patch_name].py` (naming: `luxury_report_YYYYMMDD_001.py`)
2. Define a `execute()` function that runs on `bench migrate`

```python
import frappe

def execute():
    # Your migration logic
    pass
```

## Testing

```bash
# Unit tests inherit from frappe.tests.utils.FrappeTestCase
# Place them in luxury_report/[doctype_name]/test_[doctype_name].py

# Run tests with output
bench --site local.com run-tests --app luxury_report --verbose
```

A minimal test:

```python
import frappe
from frappe.tests.utils import FrappeTestCase

class TestDocTypeName(FrappeTestCase):
    def test_something(self):
        doc = frappe.new_doc("DocType Name")
        doc.field = "value"
        doc.insert()
        self.assertEqual(doc.name, "expected_name")
```

## Code Style

- **Python**: Follow PEP 8; ruff enforces line length (110), tabs, imports sorted
- **JavaScript**: ESLint + Prettier enforce formatting; no semicolons or trailing commas
- **Comments**: Add only when the WHY is non-obvious (constraints, workarounds, hidden invariants)
- **Deletion over addition**: Remove unused code rather than commenting it out

## Permissions

Permissions are defined in the DocType JSON under `"permissions"`. Common patterns:

- `"perm_type": "read"`, `"write"`, `"submit"`, `"cancel"`, `"amend"`
- `"role": "Role Name"` (e.g., "System Manager", "Sales Manager")
- `"if_owner": 1` for owner-only permissions

Programmatic checks: override `has_permission()` in the DocType controller if needed.

## Key Notes

- The app is newly initialized; start by creating your first DocType
- Always run `bench migrate` after schema changes and `bench --site local.com clear-cache` after code changes
- Use `frappe.db.*` or `frappe.qb` for database queries; never raw SQL unless necessary
- Pre-commit hooks run automatically on staged files; fix errors before committing
- Use `bench start` during development to auto-reload on file changes
